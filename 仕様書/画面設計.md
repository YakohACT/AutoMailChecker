# 画面設計

画面はトレイと3つのウィンドウ（設定・判定履歴・お試し仕分け）だけで構成する。メール到着の通知は出さず、状態とエラーはトレイアイコンで示す。ウィンドウはWPFで作り、開いている間だけ読み込む。

## 画面一覧

| ID | 画面 | 開き方 | 目的 |
| --- | --- | --- | --- |
| SC-01 | トレイアイコンとメニュー | 常駐 | 状態の表示、停止・再開、各画面の起点 |
| SC-02 | 設定ウィンドウ「項目」タブ | メニュー「項目の設定」 | 項目の追加・編集・並べ替え、振り分け先、広告の扱い |
| SC-03 | 設定ウィンドウ「停止対象」タブ | メニュー「停止対象の設定」 | 自動停止するアプリの増減と動作の選択 |
| SC-04 | 設定ウィンドウ「全般」タブ | メニュー「全般設定」 | アカウント、自動仕分けのオン/オフ、しきい値 |
| SC-05 | 判定履歴ウィンドウ | メニュー「判定履歴」 | 結果の確認、元に戻す、誤判定の記録 |
| SC-06 | お試し仕分けダイアログ | メニュー「お試し仕分け」またはSC-05 | 過去メールでの試験的な仕分け |

共通ルール: 設定ウィンドウの3タブは保存ボタンを共有し、保存時に検証（外部仕様タブの検証規則）を行う。誤りがあれば保存せず、該当欄を赤枠にして理由を下に表示する。

## SC-01 トレイアイコンとメニュー

アイコンは運転モードとエラーの有無で変える。マウスを重ねるとツールチップに状態と未処理件数を出す。

| 状態 | アイコン | ツールチップの例 |
| --- | --- | --- |
| 稼働中 | 通常 | 稼働中 / 未処理 0件 |
| 低負荷で継続 | 通常＋青い点 | 低負荷で継続（VS Code起動中）/ 未処理 3件 |
| 判定保留 | 灰色 | 一時停止中（残り45分）/ 未処理 5件 |
| 完全停止 | 灰色＋停止マーク | 完全停止（Steamのゲームを検知）/ 未処理 12件 |
| お試し仕分け実行中 | 状態に応じたアイコンのまま | お試し仕分け 38/120件 |
| エラーあり | 上記＋赤い点 | gmail2: 認証に失敗しました（クリックで全般設定） |

メニュー（上から順）:

1. 状態の1行表示（押せない）
2. 一時停止 ▸ 30分 / 1時間 / 再開するまで
3. 完全停止
4. 再開（停止中だけ表示）
5. 判定履歴…
6. お試し仕分け…
7. 項目の設定… / 停止対象の設定… / 全般設定…
8. 終了（確認あり。処理中の1件が終わってから終了する）

## SC-02 設定ウィンドウ「項目」タブ

左に項目一覧、右に選んだ項目の編集欄を置く。一覧の並び順がそのまま優先度になる。

&#91;embedded content: SC-02 項目タブ · 一覧と編集欄\]

| 欄 | 入力 | 規則 |
| --- | --- | --- |
| 優先度 | 一覧のドラッグで並べ替え | 1からの連番を自動で振る |
| 有効 | チェック | 無効の項目はAIの選択肢から外れる |
| 表示名 | 1行テキスト | 1〜20文字、項目間で重複不可 |
| AIへの説明 | 複数行テキスト | 1〜200文字 |
| 当てはまる例 / 当てはまらない例 | 複数行（1行に1例） | 各0〜3行、1行50文字以内 |
| 振り分け先 | アカウントごとのドロップダウン | そのアカウントに既にあるフォルダーだけを表示。受信トレイ、迷惑メール、他の項目や広告で使用中のフォルダーは選べない。未設定も可（そのアカウントでは移動しない） |
| 広告の扱い | 「無視」「振り分け」の切り替え＋アカウントごとの振り分け先 | 振り分け先の規則は上と同じ |

- 項目IDは追加時に自動で振り（例: item\_7f3a）、画面には出さない
- フォルダー一覧は画面を開いたときに各アカウントへ問い合わせ、10分間使い回す。「一覧を更新」ボタンで取り直す
- 「試し判定」: 判定履歴から1通を選び、保存前の設定で判定し直して、該当項目・確信度・理由をダイアログに表示する。移動はしない。完全停止中は押せない
- 「削除」は確認ダイアログを出す。過去の判定履歴には表示名の控えが残る

## SC-03 設定ウィンドウ「停止対象」タブ

上部に「現在の検知: なし / Steamのゲーム（xxx.exe）」を表示し、その下にルールの一覧を置く。

| 欄 | 入力 | 規則 |
| --- | --- | --- |
| 有効 | チェック | 固定ルールは常にオンで変更不可 |
| 名前 | 1行テキスト | 表示用。重複可 |
| 判定方法 | 実行ファイル名 / ウィンドウタイトル / 両方 | 「両方」は両方に一致したときだけ対象 |
| 値 | 1行テキスト | 実行ファイル名は完全一致（大文字小文字は区別しない）、タイトルは部分一致 |
| 動作 | 完全停止 / 低負荷で継続 | 固定ルールは完全停止で変更不可 |

- 固定ルール（Steam、Epic、DMM）は一覧の先頭に鍵マーク付きで表示する。DMMの行だけ「インストール先フォルダー」の選択欄を持つ
- 追加ボタンは3つ: 「実行中のアプリから選ぶ」（名前と場所の一覧から選択）、「実行ファイルを参照」、「手動で追加」
- 下部に「全画面表示を検知する」チェックと「再開までの待ち時間（秒、既定60）」を置く

## SC-04 設定ウィンドウ「全般」タブ

| 区分 | 欄 | 規則 |
| --- | --- | --- |
| アカウント | ID、種類、ユーザー名、状態、「パスワードを登録」「接続テスト」 | 追加・削除は再起動が必要（保存時に案内）。パスワードは資格情報マネージャーにだけ保存し、画面にも設定ファイルにも出さない |
| 仕分け | 新着の自動仕分け（オン/オフ） | 既定オフ。お試し仕分けを1回以上行うまでは、オンにするとき確認を出す |
| 仕分け | 移動に必要な確信度（高のみ / 中以上） | 既定は中以上 |
| 表示 | エラー時にポップアップを出す | 既定オフ |
| 履歴 | 判定履歴の保持日数 | 7〜365日、既定90日 |
| AI | モデルファイル | 変更は再起動が必要。詳細な起動設定は設定ファイルで行う |

## SC-05 判定履歴ウィンドウ

上に絞り込みと当日の集計、中央に一覧、下に選んだ1件の詳細と操作ボタンを置く。

&#91;embedded content: SC-05 判定履歴 · 絞り込み、一覧、詳細\]

| 欄 | 内容 |
| --- | --- |
| 絞り込み | 期間、アカウント、結果（移動済み / 受信トレイに残した / 広告 / 失敗 / 戻した）、お試しの回 |
| 集計 | 表示中の件数、移動、受信トレイに残した数、確信度「低」の数 |
| 一覧の列 | 受信日時、アカウント、件名、該当項目、確信度、移動先（状態は移動先の文字色で示す） |
| 詳細 | 差出人、要約、判定理由、全該当項目、Message-ID |
| 操作 | 「受信トレイに戻す」（移動済みの行だけ）、「誤判定として記録」（本来の項目を選ぶ。項目なしも可） |

- 「受信トレイに戻す」は確認なしで実行し、結果を詳細欄に表示する。すでに別の場所へ移されていたら何もせずにその旨を表示する
- 一覧は新しい順。1ページ200件で、スクロールで続きを読み込む

## SC-06 お試し仕分けダイアログ

設定 → 実行中 → 完了 の3段階で表示を切り替える。

| 段階 | 表示と操作 |
| --- | --- |
| 設定 | 期間（開始日・終了日）、アカウント（複数選択）、対象フォルダー（既定は受信トレイ）、実行方法（結果の表示のみ / 実際に移動する）、件数の上限（既定200）。入力に応じて「対象 約120件 / 見込み 約3時間36分」を表示。受信トレイ以外を選ぶと実行方法は「結果の表示のみ」に固定 |
| 実行中 | 進み具合（38/120件）、現在の運転モード、「中止」ボタン。ダイアログを閉じても裏で続く |
| 完了 | 項目ごとの件数、確信度「低」の件数、広告の件数、失敗の件数。「結果を判定履歴で見る」「この回の移動をまとめて戻す」（実際に移動した回だけ）。判定履歴で誤判定を記録すると、この画面に「この回の精度」（重要の見逃し率、誤振り分け率）が出る |

見込み時間は1件108秒で計算し、実測の平均が溜まったらその値に置き換える。

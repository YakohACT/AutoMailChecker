# クラス図・シーケンス図

ソースは5つのプロジェクト（＋テスト）に分け、依存は必ずCoreへ向ける。IMAP・llama-server・Windowsを扱うクラスはCoreのインターフェースを実装する側に置き、差し替えとテストをその入れ替えだけで済ませる。仕様書6章のクラス構成を、処理の流れを担うサービスまで具体化したものである。

実線はコード上の依存、点線は起動時に具体クラスを組み立てるだけの関係である。AppはWindowsも同じように組み立てる。Coreは他のどのプロジェクトも参照しない。

### 主要クラス

| クラス | 置き場所 | 主なメソッド | 役割 |
| --- | --- | --- | --- |
| MailProcessingService | App | RunAsync | キューから1件ずつ取り出し、除外判定→本文取得→AI判定→振り分け→保存を進める。運転モードが判定保留・完全停止なら次の1件を取らない |
| ActionPolicy | Core | Decide | 確信度 → 広告 → 優先度の順に見て、移動先（項目・広告・なし）と結果の値（outcome）を返す。入出力なし |
| SenderFilter | Core | IsExcluded | 除外リスト（アドレス完全一致・ドメイン一致）との照合 |
| BodyPreprocessor | Core | ToPlainText | HTMLのテキスト化、引用と署名の除去、切り詰め（プロンプト設計タブ） |
| ActionExecutor | App | ExecuteAsync | ActionPolicyの決定どおりにIItemFolderMoverを呼び、COPYUIDを受け取る |
| TrialRunner | App | StartAsync / CancelAsync / RollbackAsync | お試しの対象を集めてキューに積み、終わったら集計する |
| UndoService | App | UndoAsync | 1件を受信トレイに戻し、誤判定を記録する |
| ConfigService | App | Current / Changed / SaveAsync | config.jsoncの読み書き、検証、変更の通知 |
| SqliteStateStore | App | 各リポジトリ | E-R図の8つの表を扱う |
| AccountWatcher | Mail | StartAsync | 1アカウント1つ。IDLEで新着を受け、未処理UIDをキューに積む。切断時は再接続 |
| ImapMailReader | Mail | FetchHeaderAsync / FetchSnapshotAsync / SearchByDateAsync | 読み取りはすべてBODY.PEEK |
| ImapItemFolderMover | Mail | 移動3種（下のインターフェース） | アカウントごとに1つ。移動先は設定から引く |
| LlamaClassifier | Llm | ClassifyAsync | PromptBuilderとSchemaBuilderで要求を作り、送信し、結果を検証する |
| LlamaServerManager | Llm | StartAsync / StopAsync | 通常・低負荷のどちらかの設定で起動し、/healthを待つ。APIキーは起動のたびに作る |
| PauseController | Windows | Current / Changed | 5秒ごとに停止対象を検知し、手動指示と合わせて運転モードを決める |
| ProcessRuleMatcher / FullscreenDetector | Windows | Match / IsFullscreen | 停止対象の判定（外部仕様タブのWindows API） |

### インターフェース定義

```csharp
namespace MailSentinel.Core;

public enum RunMode { Running, LowLoad, Held, Stopped }   // 稼働中・低負荷・判定保留・完全停止
public enum Confidence { High, Medium, Low }
public enum LlmProfile { Normal, LowLoad }

public readonly record struct ItemId(string Value);
public readonly record struct MailRef(string AccountId, string Folder, uint UidValidity, uint Uid);

public sealed record MailHeader(MailRef Ref, string MessageId, string From, string Subject, DateTimeOffset Received);
public sealed record MailSnapshot(MailHeader Header, string BodyText, IReadOnlyList<string> AttachmentNames);

public sealed record Judgement(
    bool IsAdvertisement, IReadOnlyList<ItemId> MatchedItems, Confidence Confidence,
    string Summary, string Reason);

// ActionPolicyの結果。Targetがnullなら移動しない
public sealed record MoveDecision(MoveTarget? Target, string Outcome);
public abstract record MoveTarget;
public sealed record ItemTarget(ItemId Item) : MoveTarget;
public sealed record AdvertisementTarget : MoveTarget;

public interface IMailReader          // アカウントごとに1つ
{
    string AccountId { get; }
    Task<MailHeader> FetchHeaderAsync(MailRef mail, CancellationToken ct);
    Task<MailSnapshot> FetchSnapshotAsync(MailRef mail, int maxBodyChars, CancellationToken ct);
    Task<IReadOnlyList<MailRef>> SearchByDateAsync(string folder, DateOnly from, DateOnly to, CancellationToken ct);
}

public interface IItemFolderMover     // アカウントごとに1つ。メールを変更するのはこの3つだけ
{
    string AccountId { get; }
    Task<MovedMailRef> MoveToItemFolderAsync(MailRef mail, ItemId item, CancellationToken ct);
    Task<MovedMailRef> MoveToAdvertisementFolderAsync(MailRef mail, CancellationToken ct);
    Task<UndoResult> MoveBackToInboxAsync(MovedMailRef moved, CancellationToken ct);  // ユーザー操作からだけ
}

public interface IMailClassifier
{
    Task<Judgement> ClassifyAsync(MailSnapshot mail, IReadOnlyList<ItemDefinition> items, CancellationToken ct);
}

public interface ILlmRuntime
{
    LlmProfile? Running { get; }
    Task StartAsync(LlmProfile profile, CancellationToken ct);   // /healthが200になるまで待つ
    Task StopAsync(CancellationToken ct);
}

public interface IRunModeSource
{
    RunMode Current { get; }
    event EventHandler<RunMode> Changed;
}
```

IStateStore（E-R図の表ごとのリポジトリ）とIConfigProvider（外部仕様タブの設定項目を型付きで返す）もCoreに置く。

### SQ-4 お試し仕分け

SQ-1の処理を使い回すため、図は省き差分だけを示す。

1. TrialDialogがTrialRunner.StartAsyncを呼ぶ（期間、アカウント、フォルダー、実行方法、件数の上限）
2. 各アカウントでImapMailReader.SearchByDateAsyncを呼び、対象のUIDを集める
3. 上限を超えたら受信日時順に並べ、等間隔に間引く
4. trial\_runを作り、queue\_itemにtrial\_run\_id付きで積む。新着（trial\_run\_idがNULL）は常にお試しより先に処理する
5. MailProcessingServiceがSQ-1の手順4〜13と同じ手順で処理する。「結果の表示のみ」なら手順11・12を行わずoutcomeをplannedにする。起点UIDとlast\_processed\_uidは更新しない
6. 全件が終わったらtrial\_runをdoneにし、ダイアログに集計を返す
7. 「まとめて戻す」は、その回のmove\_recordを1件ずつUndoServiceで戻し、最後にrolled\_back\_atを記録する

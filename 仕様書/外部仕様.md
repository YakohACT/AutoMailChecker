# 外部仕様

アプリが外とやり取りするのは、設定ファイル、IMAPサーバー、llama-server、Windowsの4つだけである。IMAPはここに挙げたコマンドだけを使い、それ以外の変更系コマンド（APPEND、CREATE、DELETE、RENAME、既読などのフラグ変更）を呼ぶコードは持たない。

## ファイルの配置

| ファイル | 場所 | 内容 |
| --- | --- | --- |
| 設定 | `%APPDATA%\MailSentinel\config.jsonc` | 下の設定項目。画面から保存する前に`config.jsonc.bak`へ退避する |
| 状態DB | `%LOCALAPPDATA%\MailSentinel\state.db` | E-R図の8つの表 |
| ログ | `%LOCALAPPDATA%\MailSentinel\logs\yyyy-MM-dd.log` | 14日で削除。本文は書かない |
| APIキー | `%LOCALAPPDATA%\MailSentinel\run\llama.key` | llama-serverの起動ごとに作り、終了時に消す。本人だけが読める権限にする |
| パスワード | Windows資格情報マネージャー「MailSentinel/＜アカウントID＞」 | 汎用資格情報として保存 |

画面から保存すると、設定ファイルのコメントは残らない。ファイルを直接編集して使う場合は、画面からの保存と併用しないか、.bakから戻す。

### 保存時の検証

- 項目IDと優先度に重複がない
- 同じアカウントの中で、振り分け先フォルダー（広告用を含む）が項目間で重複しない
- foldersのキーはaccountsにあるIDで、値はそのアカウントに実在し、受信トレイと迷惑メールではない
- watchFoldersに迷惑メールフォルダーを含まない
- 数値が範囲内にある

画面からの保存では、誤りが1つでもあれば保存しない。ファイルを直接編集した場合は、誤りのある項目だけ前の値（なければ既定値）で動かし、トレイアイコンで知らせる。

## IMAPの使い方

| 用途 | コマンド | 備考 |
| --- | --- | --- |
| 接続と認証 | TLS（993番）、AUTHENTICATE PLAINまたはLOGIN | アプリ用パスワード |
| 機能の確認 | CAPABILITY | IDLE、MOVE、UIDPLUS、SPECIAL-USEの有無を記録 |
| フォルダー一覧 | LIST（SPECIAL-USE属性付き） | 振り分け先の候補と、迷惑メール（\\Junk）の判別 |
| 監視 | SELECT INBOX、IDLE / DONE | 移動のため読み書きモードで開く。IDLEは9分ごとに張り直す |
| 新着の検索 | UID SEARCH UID ＜前回＋1＞:\* |  |
| お試しの検索 | UID SEARCH SINCE ＜開始日＞ BEFORE ＜終了日の翌日＞ | 日付はサーバー側の受信日で比べられる |
| ヘッダー取得 | UID FETCH (ENVELOPE BODYSTRUCTURE BODY.PEEK\[HEADER.FIELDS (FROM SUBJECT DATE MESSAGE-ID)\]) | 既読にしない |
| 本文取得 | UID FETCH BODY.PEEK\[＜パート番号＞\] | text/plainかtext/htmlの1パートだけ |
| 移動 | UID MOVE ＜uid＞ ＜フォルダー＞ | 応答のCOPYUIDを記録 |
| 移動（MOVE非対応時） | UID COPY → UID STORE +FLAGS.SILENT (\\Deleted) → UID EXPUNGE ＜uid＞ | UID EXPUNGEにはUIDPLUSが必要。どちらもなければ移動しない |
| 元に戻す | SELECT ＜移動先＞ → UID MOVE ＜dest\_uid＞ INBOX | dest\_uidがなければUID SEARCH HEADER Message-IDで探す |
| 生存確認 | NOOP | IDLEが使えないときの5分ごとの確認にも使う |

Gmailではフォルダーがラベルに当たり、受信トレイからのMOVEは「受信トレイ」ラベルを外して移動先ラベルを付ける操作になる。監視用の接続はアカウントごとに1本ずつ常時保つ（計4本）。本文の取得と移動は、必要なときだけ開く別の接続で行い、5分使わなければ閉じる（IDLE中の接続では他のコマンドを送れないため）。

## llama-serverとのやり取り

| 引数 | 通常 | 低負荷で継続 |
| --- | --- | --- |
| -m | llm.model | 同じ |
| --host / --port | 127.0.0.1 / llm.port | 同じ |
| --api-key-file | 起動ごとに作るキー | 同じ |
| -c / -np | llm.ctxSize / 1 | 同じ |
| -ngl | 指定しない（自動） | 0 |
| --n-cpu-moe | llm.nCpuMoe（null以外のとき） | 指定しない |
| -t | llm.threads | 2 |
| その他 | --no-webui --no-mmproj --reasoning off --prio -1 | 同じ |

- 起動の確認: GET /healthが200を返したら準備完了。120秒以内に200にならなければ失敗とし、3回まで起動し直す
- 判定: POST /v1/chat/completions。ヘッダーにAuthorization: Bearer ＜キー＞。要求の形はプロンプト設計タブ
- 終了: 子プロセスはジョブオブジェクトに入れ、アプリ本体が異常終了しても一緒に終わるようにする

## Windows API

| 用途 | 使うもの | 備考 |
| --- | --- | --- |
| 全画面の検知 | SHQueryUserNotificationState | QUNS\_BUSYまたはQUNS\_RUNNING\_D3D\_FULL\_SCREENで検知 |
| プロセスの列挙 | Process.GetProcessesとQueryFullProcessImageName | 新しいプロセスIDだけ実行ファイルの場所を調べる |
| ウィンドウタイトル | EnumWindowsとGetWindowText | タイトルのルールがあるときだけ |
| Steamの場所 | レジストリ HKCU\\Software\\Valve\\Steam のSteamPath → steamapps\\libraryfolders.vdf | 起動時と設定の保存時に読む |
| Epicのインストール先 | C:\\ProgramData\\Epic\\EpicGamesLauncher\\Data\\Manifests の各ファイルのInstallLocation | 同上 |
| 資格情報 | CredRead / CredWrite（汎用資格情報） |  |
| 自動起動 | タスクスケジューラ（ログオン時、管理者権限なし） |  |
| llama-serverの後始末 | ジョブオブジェクト（JOB\_OBJECT\_LIMIT\_KILL\_ON\_JOB\_CLOSE） |  |

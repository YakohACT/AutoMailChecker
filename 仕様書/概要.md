# MailSentinel 設計書

Oct 16, 2026 · @Haruki Yasukawa

## 1. 本書の位置づけ

本書は[メール監視・AI仕分けソフト 仕様書](https://claude.ai/code/artifact/63ae8e25-7868-44a9-bf5e-d0428ca15fc6)（2026-10-15時点）を、実装できる粒度まで具体化した設計書である。「何を作るか」は仕様書、「どう作るか」は本書が扱う。両者が食い違う場合は仕様書を正とし、本書を直す。

- 対象: MailSentinel（Windows常駐、iCloud 1・Gmail 3の計4アカウント）
- 範囲: 画面、データベース、クラス構成と処理の流れ、AIへの指示文、外部とのやり取り、テスト
- 範囲外: 配布用インストーラー、macOS/Linux対応

## 2. 設計書の構成

設計書は6つのタブに分かれる。実装はクラス・シーケンスとE-R図から始め、画面は処理の流れが固まってから作るとよい。

| 設計書 | 内容 | 主な決定 |
| --- | --- | --- |
| 画面設計 | トレイと3つのウィンドウ（6画面） | メール到着の通知は出さず、状態とエラーはトレイアイコンで示す |
| E-R図 | SQLiteの8つの表 | 項目とアカウントの定義は設定ファイル側に置き、DBはIDと判定時点の控えだけを持つ |
| クラス・シーケンス | 5つのプロジェクトのクラス構成と、4つの処理の流れ | 依存はCoreへ向ける。メールを変更する操作は3つのメソッドだけ |
| プロンプト設計 | AIへの指示文・メール・出力形式 | 指示文を毎回同じにしてキャッシュを効かせ、出力はJSONスキーマで固定する |
| 外部仕様 | 設定ファイル、IMAP、llama-server、Windows API | 使うIMAPコマンドを限定し、それ以外の変更系コマンドは呼べないようにする |
| テスト設計 | 単体・結合・精度評価・性能 | 精度はアプリのお試し仕分けと誤判定記録だけで測れるようにする |

## 3. 前提となる技術構成と用語

| 区分 | 採用技術 |
| --- | --- |
| 言語・実行環境 | C# / .NET 10（Generic Hostで常駐） |
| 画面 | トレイ: WinFormsのNotifyIcon、各ウィンドウ: WPF（開いている間だけ読み込む） |
| メール | MailKit（IMAP、IDLE、MOVE） |
| 状態の保存 | SQLite（Microsoft.Data.Sqlite） |
| 設定 | config.jsonc（コメント付きJSON）。画面からの編集もこのファイルに書き戻す |
| AI | llama.cppのllama-server（別プロセス、127.0.0.1のみ）、既定モデルQwen3.5-9B |
| 資格情報 | Windows資格情報マネージャー |

| 用語 | 意味 |
| --- | --- |
| 項目 | ユーザーが定義する仕分けの分類（重要、予約関連、決済履歴、給与明細） |
| 判定 | AIが1通について返す結果（広告か、該当項目、確信度、要約、理由） |
| 振り分け | 判定から移動先を決めてIMAPで移動すること。決めるのはアプリ、AIではない |
| 起点UID | 初回起動時に記録する各フォルダーの最大UID。これ以前は自動処理しない |
| 運転モード | 稼働中・低負荷で継続・判定保留・完全停止の4状態 |
| お試し仕分け | 期間を指定した過去メールで行う試験的な仕分け |
